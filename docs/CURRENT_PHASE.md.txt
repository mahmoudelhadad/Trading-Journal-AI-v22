## Objective

Connect the fully-built Advanced Filters capability (Phase 14) to the
application's shared trades pipeline, so a saved FilterGroup becomes an
active global lens applied on top of the existing account/market
filters across every consuming page.

Before this phase, SettingsModal passed an empty function to
SavedFiltersList's onApply: a user could build a multi-condition AND/OR
filter, preview its match count, name it, save it and favorite it, and
clicking "Apply" did nothing. That is now a working feature.

The phase's central safety property — with no active filter the visible
trade set is identical to before — was established by three independent
mechanisms rather than asserted (see Verification below).

## Scope (as delivered)

1. calculations/visibleTrades.ts (new, pure L3) —
   selectVisibleTrades(trades, accFilter, mktFilter, activeGroup).
   Holds the account/market predicate moved VERBATIM out of
   useFilters.applyFilters, composed with the existing
   applyFilterGroup(). Fixed composition order: account → market →
   group.
2. One-line barrel addition to calculations/index.ts.
3. useFilters() gained activeFilter / setActiveFilter /
   clearActiveFilter. In-memory only, matching the existing
   account/market filter semantics. applyFilters() is now a thin
   useCallback delegating to selectVisibleTrades(); its exported
   signature is unchanged.
4. SettingsModal gained an optional onApplyFilter, replacing the dead
   no-op. App.jsx supplies it: snapshot the group, close the modal.
5. Snapshot semantics via structuredClone — deleting or editing the
   source SavedFilter cannot change the active view.
6. FilterBar gained four additive optional props rendering the active
   filter chip: name, "N of M trades", and a ✕ clear control.
7. pages/Backtest.tsx continues to receive UNFILTERED allTrades.

## Known Risks

Introduced by this phase:

- Low/Medium: fixed-threshold analyses — notably pages/Insights.tsx —
  now run against arbitrarily small filtered samples. Its thresholds
  and messages carry identical visual confidence at 3 trades as at 300.
  A foreseeable consequence of making the trade set user-narrowable;
  no minimum-sample guard exists. Out of scope for this phase.
- Low: the chip's "N of M" denominator is the TOTAL unfiltered count,
  so when an account or market filter is also active the ratio
  understates how much of the reduction came from the chip's own
  filter. Behaviorally correct, cosmetically imprecise. Observed
  directly during manual scenario (f).

Carried forward, unchanged and unrelated:

- Medium: onIndexedDbBlocked has no subscriber (G-3, Phase 6h).
  Unreachable at DATABASE_VERSION = 1, confirmed still 1.
- Low/Medium items from Phase 6g-2/6h (stopLeaderElection cannot
  interrupt an executing callback; local-persistence notice
  read-failure labelling).
- The 7 pre-existing lint warnings.

## Next Phase

Not yet selected — requires the standard re-derivation-and-approval
workflow before any scope is set.

Recommended candidate: AI Insights Layer. Phase 22 was sequenced ahead
of it deliberately, and the reason now holds concretely: an AI feature
needs a defined subset of trades to reason about, and FilterGroup is
now that subset object — one concept the user can view through,
backtest, and (in a future phase) ask questions about. Establishing the
single composed filtering pipeline first also removes the pressure for
an AI layer to grow its own trade-selection logic, which would violate
Playbook §3.

Alternative candidate, smaller: wire components/trade/TradeReview.tsx.
It remains the project's second dead-end capability — a user can define
checklist templates and custom fields in Settings but cannot apply them
to any trade, because TradeReview.tsx has zero importers. Narrower in
value than the AI layer and more intrusive (it requires modifying
TradeForm.tsx or TradeRow.tsx and adding a persistence decision), but
it closes a visible gap.

Neither is approved. Also still open and unscoped: Prop Firm Tracker
and Position Size Calculator (never migrated from the original app),
and Sync Engine enablement (built, flagged off).
