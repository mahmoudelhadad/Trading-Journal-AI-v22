## Objective

Repair the advertised-but-non-functional Excel import, correct browser quota
classification so the existing tailored storage-full notice can be selected,
and make the running build identifiable from the application — without
architecture, dependency, schema, or format change.

---

## Delivered Scope — three deliverables

1. **Honest Excel/XLSX import.** The migrated wizard relied on a global
   `XLSX` that never existed (an ambient `declare` kept typecheck green), so
   every workbook upload failed with "Excel library not loaded" while the UI
   advertised Excel support. The parser is now loaded dynamically, only when
   an Excel import is invoked, using the already-declared `xlsx` dependency.
   `.xlsx`/`.xls` feed the same normalized `string[][]` pipeline as CSV.

2. **Correct quota classification.** A browser `QuotaExceededError` is a
   `DOMException` identified by `.name`; the reporter classified only on
   `.kind`, so quota exhaustion showed the generic notice. `.name` is now
   consulted only when no `.kind` exists, leaving every existing IndexedDB
   classification authoritative and the non-throwing facade unchanged.

3. **Release/build visibility.** General Settings shows
   `v<version> · build <short commit>`, sourced from `package.json` and from
   `GITHUB_SHA` / local git / `dev`.

## Import Contract

- Excel parsing is dynamic and on demand; it is never loaded during normal
  application startup.
- `.xlsx` and `.xls` produce the same `string[][]` shape as CSV and feed the
  unchanged `processRows()` pipeline.
- CSV behavior is untouched.
- Excel failures, including a failed lazy-chunk fetch, surface through the
  existing `Excel error: ...` channel.
- No import envelope, DTO, adapter, source identity, or schema was
  introduced.

Measured parser nuance (bounds what this guarantees):
- SheetJS does not throw on all malformed input — unrecognized bytes are
  tolerated and read as a single-cell text sheet.
- A structurally broken workbook (e.g. a truncated ZIP) does throw and is
  surfaced gracefully.
- Unrecognized junk is stopped downstream instead: `processRows()` requires a
  header row of more than three non-empty cells and rejects it with "Could
  not detect headers."
