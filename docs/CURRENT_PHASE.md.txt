# Current Phase

## Phase

Phase 31 — Recovery Bin Permanent-Deletion Safety

Status:

COMPLETE

---

## Objective

Require explicit confirmation before permanently deleting one Recovery Bin
entry or emptying the entire Recovery Bin, while preserving the existing
destructive callbacks and downstream behavior.

---

## Delivered Scope

- Added browser-native confirmation at the single-entry permanent-delete UI
  boundary.
- Added a stronger browser-native confirmation at the Empty Bin UI boundary.
- Cancellation invokes no destructive callback and therefore initiates no
  Recovery Bin state or persistence mutation.
- Single-entry acceptance invokes the existing permanent-delete callback
  exactly once with the exact selected entry ID.
- Empty Bin acceptance invokes the existing empty-bin callback exactly once.
- Restore, Restore All, empty-state, retention, expiry, persistence, and
  active-trade behavior remain unchanged.
- No automated test was added because the approved RFC kept this browser
  confirmation wiring outside the existing Node-only test suite.

---

## Exact Confirmation Strings

Single entry:

"Permanently delete this Recovery Bin entry? This action cannot be undone through the Recovery Bin."

Empty Bin:

"Permanently delete ALL Recovery Bin entries? This action cannot be undone through the Recovery Bin."

The strings make no promise about backup, Restore Point, cloud,
transactional, browser-level, or other recovery availability.

---

## Confirmation Boundary and Semantics

RecoveryBinPanel owns both prompts next to their destructive controls.

Cancellation:

- returns without invoking the supplied destructive callback;
- initiates no Recovery Bin React state update or persistence mutation;
- leaves active trades and all Recovery Bin entries unchanged;
- invokes no Restore or Restore All callback.

Single-entry acceptance:

- invokes `onPermanentlyDelete` exactly once;
- passes the selected `entry.id` through exactly;
- removes only the matching entry through unchanged hook behavior;
- leaves other Recovery Bin entries and active trades unchanged.

Empty Bin acceptance:

- invokes `onEmptyBin` exactly once;
- preserves the existing clear-all behavior;
- does not modify active trades.

App, SettingsModal, useRecoveryBin, and the existing persistence effect remain
unchanged. No optimistic mutation occurs before confirmation.

---

## Empty-State Behavior

The existing `entries.length > 0` guard remains unchanged. Restore All and
Empty Bin are hidden when the Recovery Bin is empty, and individual
permanent-delete controls exist only for rendered entries.
