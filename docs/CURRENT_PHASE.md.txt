## Objective

Prevent authenticated users sharing one browser profile from reading or
mutating another authenticated user's browser-local journal data, while
preserving portable Backup/Restore and handling pre-existing global local data
through an explicit, fail-closed ownership contract.

## Storage Namespace Contract

The logical inventory is frozen at 14 keys. Each authenticated logical key is
physically stored as:

`fxj:user:v1:<encodeURIComponent(exactUserId)>:<logicalKey>`

The exact authenticated UUID is validated and preserved; its case and bytes
are not normalized. Storage routing is captured by the authenticated session
and context, not selected from mutable global current-user state. The keyed
session identity is the exact authenticated `user.id`.

---

## Legacy Ownership Contract

Physical raw presence under any recognized legacy key is authoritative.
Values such as `[]`, `{}`, `null`, and default-looking data remain claim
candidates. Malformed recognized JSON is quarantined rather than normalized or
hydrated.

The five authority states are:

- `legacy_absent`
- `legacy_detected_unclaimed`
- `claim_in_progress`
- `claim_failed_retryable`
- `claim_verified`

Claim and decline are explicit user choices. A claim reserves an owner before
copying. Only that reserved owner may retry or overwrite partial destination
residue. Partial residue is not authority, and verified ownership is not
established until `claim_verified` is committed and read back last. The
preserved global source is not deleted.

---

## Locking and Verification Contract

Legacy transitions are serialized by the Web Lock:

`trading-journal-ai:legacy-claim:v1`

No LocalStorage lease or lock polyfill exists. Claim freezes a canonical
SHA-256 digest, copies the eligible snapshot, reads destination values back,
re-digests the preserved source, verifies the completed copy and registry, and
only then establishes `claim_verified` authority.

---

## Sync Cursor Rule

The global legacy Sync cursor participates in physical detection, the frozen
snapshot, and the source digest. It remains preserved globally and is
intentionally not transferred into the authenticated namespace. A newly
scoped Sync cursor starts absent.

---

## IndexedDB Preflight

The existing global `trading-journal-ai` database marker is inspected
read-only. Preflight must not create an absent database. Marker-present,
unreadable, or unsafe enumeration/read conditions fail closed. Runtime Gate A
was A1: the database was absent in the tested real browser profile. This phase
does not establish per-user IndexedDB.

---

## Authenticated React and Persistence Routing

The implemented ownership/session boundary is:

`AuthProvider → AuthGate → LocalOwnershipGate → keyed LocalOwnershipSession → UserStorageProvider → App/notice`

The captured scoped facade/database serves accounts, trades, lists, settings,
advanced filters, Trade Review, Recovery Bin, Restore Points, Backtests,
Backup/Restore, and the Phase 32B local database/stamping paths. Dormant global
compatibility accessors are not normal authenticated write authority.

Authenticated startup does not start the legacy global Sync/Cutover path.
Enabled Sync or Cutover fails closed at LocalOwnershipGate.
SyncConflictReview is not mounted on the authenticated scoped path.

---

## Backup and Restore

- Backup reads the current authenticated scope only.
- The existing portable v1/v2 payload remains logical and user-ID agnostic;
  physical namespace keys and owner UUID requirements are not exported.
- Restore writes only the current authenticated scope.
- Restore Points remain user-scoped and excluded from portable backup.
- Sync cursors remain excluded.
- Explicit A→B restore portability was verified: A's backup replaced B's
  disposable journal data without mutating A, and B's Restore Points remained
  B-scoped.

## Known Limitations

- An explicit wrong-user reservation can strand legacy ownership pending
  future approved handling.
- The global legacy source remains preserved rather than deleted.
- Broader authentication-transition cancellation/generation is deferred.
- Per-user IndexedDB is deferred.
- Unsupported or unsafe global IndexedDB enumeration fails closed.
- Direct session replacement and the failure paths listed above retain their
  accurately bounded automated/source-only evidence.

---

## Explicit Exclusions

Phase 32B does not establish:

- per-user IndexedDB;
- full Sync reactivation;
- full Cutover reactivation;
- general auth-transition cancellation/generation;
- historical data repair beyond the frozen legacy-ownership flow; or
- Futures functionality.

No dependency, configuration, environment, schema, or calculation change was
made.
