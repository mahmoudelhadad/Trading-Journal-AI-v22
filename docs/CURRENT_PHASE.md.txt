## Objective

Establish a provider-independent historical market-data foundation that a later
Backtest replay engine can read, without touching journal storage authority and
without acquiring a paid data dependency.

v1.6 adds the ability to ingest, normalize, store and read historical bars. It
adds no user-facing behaviour.

---

## Frozen Invariant

A NinjaTrader 1-minute historical export is ingested into a canonical,
contract-identified, UTC start-of-bar representation stored in a **separate**
IndexedDB database, readable through a **provider-independent** range reader,
with **zero** effect on journal storage, and **fully removable** without
touching journal data.

---

## Why This Is a New Data Domain

The feature currently named Backtest is filter-based analytics over already
journalled trades. It contains no market data, no time axis and no order model,
so historical bars had no existing home.

They also do not behave like journal data. A trade is user-authored and losing
it is harm; a historical bar is an external market fact the application caches,
and losing it costs a re-import. AD-023 records that as a third data class — a
reconstructable cache — distinct from AD-014's Class A synced business data and
Class B unsynced local data, both of which are user-owned.

## Delivered Scope

1. **NinjaTrader historical adapter.** One module owns the semicolon grammar,
   the `yyyyMMdd HHmmss` stamp, the absent header row, the `MM-YY` expiry
   notation, and the End-of-Bar convention. Nothing downstream knows any of it.
   The existing trade-import CSV parser was neither reused nor modified.

2. **Deterministic timestamp normalization.** Source is UTC End-of-Bar, so a
   1-minute bar's canonical start is `sourceEnd − 60000` and the bar covers
   `[start, start + 60000)`. Any other timeframe/convention pair is refused
   rather than guessed at.

3. **Provider-neutral series identity.** `{ root, expiryYear, expiryMonth,
   timeframe }`, rendered as `NQ|2016|03|1m`. No provider token appears in the
   identity, a chunk id, a bar, or a read request; provider lives only in import
   provenance.

4. **Individual contracts as stored truth.** `NQ 03-16` and `NQ 06-16` are
   separate series. Continuous and back-adjusted views remain derivable and are
   never the stored form.

5. **Observation-faithful storage.** Absent minutes stay absent. No
   previous-close filling, no zero-volume padding, no cross-instrument alignment
   candles.

6. **Atomic visibility.** Immutable revision-bearing chunks plus a single
   manifest write as the only visibility-changing operation. A changed day is
   written at `activeRevision + 1`, never over the committed chunk, and the
   reader resolves the manifest before reading anything.

7. **Serialized mutation.** On the default production path — the path every
   production caller uses — each import, delete and cache clear runs inside one
   origin-wide exclusive Web Lock, and committed state is re-read inside it. The
   mutation APIs also expose an optional `runExclusive` seam, described under
   Automated Verification, which a controlled caller can supply to substitute a
   different runner; that seam is how the Node-only harness reaches this logic.

8. **Fail-safe destruction.** `deleteSeries` tombstones with the cleanup map
   preserved, so an interrupted deletion resumes deterministically;
   `clearHistoricalCache` clears manifests before payload.

9. **Observed availability, never completeness.** A source file records the bars
   it contains, not the export window requested, so no API claims coverage and
   no universal absence count is stored.

10. **Storage failure is never reported as absence.** The chunk source
    distinguishes a value, a proven absence, and an operational failure. The
    reader emits `read_failed` whenever storage prevented it from establishing
    absence, and reserves `series_unavailable` for absence or a deleting state
    it actually observed.

11. **A zero-bar import is rejected unconditionally,** before any read or write
    and regardless of whether the series exists, so no series can hold an
    active manifest with no observations.

## Storage Architecture

A separate IndexedDB database, `trading-journal-ai-marketdata` version 1, with
exactly two object stores and **no indexes**:

- `series`, keyed by `seriesId` — the committed manifest, its lifecycle state,
  and import provenance.
- `bar_chunks`, keyed by `chunkId` — one UTC calendar day of column-oriented
  bars per record.

The generic `services/indexedDb.ts` primitive is reused **unmodified**; the
market-data database is a new caller of it, not a new primitive. Every access
path is a primary-key `get`, which is why the absent cursor and index support is
not a constraint.

The journal database keeps its name, its version, and its six object stores.

## Automated Verification

- TypeScript: 0 errors.
- ESLint: 0 errors and exactly 7 pre-existing warnings; no new warning.
- Tests: **594 passing across 29 files** — the full 460-test v1.5 baseline
  preserved unchanged across its 25 files, plus 134 new tests across 4 new
  files. No existing test was weakened, renamed or removed.
- Production build: passed.
- `git diff --check`: clean.
- Dependency, test-framework, and test-configuration changes: none.

**Mutation proof.** Fourteen invariants were each deliberately broken before
acceptance and each turned the corresponding test red before being reverted:
the `−60000` timestamp shift; expiry in series identity; conflict rejection;
gap preservation; chunk-before-manifest commit ordering; market-database
separation from the journal database; reader ordering; manifest-gated chunk
reads; `activeRevision + 1` allocation; provider absence from the read request
(a compile-time proof); reading committed state before acquiring the mutation
lock; tombstone map preservation; manifest-before-payload clear ordering; and
the deleting-state visibility check.

**Test-harness boundary, recorded rather than concealed.** `vitest.config.ts`
sets `environment: 'node'` with no DOM and no IndexedDB. Decision and ordering
logic is therefore proven in Node against injected fakes, and real host
behaviour — IndexedDB, structured clone, Web Crypto, cross-tab Web Locks — is
proven at runtime acceptance. No jsdom and no fake-IndexedDB dependency was
added.

**One production seam exists purely to make that split testable, and it is
disclosed rather than hidden.** The three storage mutation APIs
(`commitImport`, `deleteSeries`, `clearHistoricalCache`) accept an optional
`runExclusive` runner; when it is omitted — as it is on every production call
path — the origin-wide Web Lock is used. It exists because the real Web Locks
API is host behaviour a Node-only harness cannot reach, and it is confined to
`services/marketDataStore.ts`: it appears in no Replay-facing type, and
`HistoricalBarReader` has no locking concept at all. The consequence is that
the unconditional "every mutation holds the lock" guarantee holds for callers
that do not override the runner; a caller that deliberately injects a
passthrough can bypass it. Runtime acceptance exercised the default path,
including cross-tab exclusion against a second real browser tab.

One deviation from the frozen test plan is recorded: the planned source-text
scan asserting that market-data modules never import `pipValues` required
`node:fs` type declarations this project does not carry, and adding `@types/node`
would have been a dependency change. The property is instead proven
behaviourally — roots that exist in `PIP_TABLE` but not in the market-data
domain are rejected — with `pipValues` imported by the test only, as evidence.

## Runtime Evidence

Localhost Runtime Acceptance **PASSED** — RA-1 through RA-14 plus RA-C1 through
RA-C5. A dedicated clean browser profile was used; the primary journal account
was never used, opened or inspected, and no journal database existed in that
profile at any point.

- Real exports ingested at **2700**, **2729** and **2557** bars, matching source
  row counts exactly, into three provider-neutral series with no id collision.
- End-of-Bar normalization exact on every file. Canonical first bars at
  `2016-03-01T05:00:00Z` for March and `2016-06-01T04:00:00Z` for June — the
  one-hour difference is real EST/EDT evidence that no fixed UTC offset exists
  anywhere in the path.
- Browser SHA-256 produced three distinct 64-hex digests, all stored in
  provenance, and reproduced exactly on re-reading the same file.
- Gap preservation held on all three series: reader observations identical to
  source observations, zero fabricated bars, zero bars at absent minutes, no
  flat zero-volume candle anywhere. March absent-minute counts were **180** and
  **151** over 2880-slot windows.
- NQ and ES intersected at **2700** with **29** ES-only minutes and **0**
  NQ-only minutes; no NQ bar was invented at any ES-only minute, and alignment
  is by timestamp rather than array index.
- A full page reload preserved every series, count, revision, provenance entry
  and checksum, with column arrays surviving structured clone intact.
- An identical re-import wrote **no chunk**, bumped **no revision**, left the
  committed block unchanged, and recorded 2700 idempotent duplicates.
- A conflicting bar was rejected with zero writes — no chunk, no revision, and
  no provenance entry — and the stored bar was unchanged.
- Reader range behaviour was correct across a day boundary: strictly ascending,
  half-open at both ends, one-minute range returning one bar, empty range
  returning none, unknown series reported unavailable.
- Cross-tab exclusion was demonstrated with a second real browser tab holding
  the production lock; the committing tab blocked and then succeeded. Two
  competing commits produced the exact union with no lost update.
- Deleting one series removed its record and chunks while leaving the other two
  intact. A tombstoned deletion survived a real page reload with its cleanup map
  preserved, stayed invisible throughout, and resumed to completion.
- Import versus clear serialized with no partial mixture and no manifest
  referencing missing payload. The fail-safe clear window left nothing visible
  and nothing reachable, and re-running completed cleanup.
- Journal isolation held: the only database created was
  `trading-journal-ai-marketdata`, no journal database was ever created, and
  LocalStorage was unchanged from the pre-acceptance snapshot.

Two unplanned negative tests also passed. A mislabelled file selected during
acceptance — ES content declared as NQ — was rejected as a conflict with zero
writes, exercising the hazard that contract identity appears in no source row.
A repeated commit was absorbed idempotently, confirmed by its provenance entry

## Architecture Decision

**AD-023 was recorded**: historical market data is a reconstructable cache
domain in its own IndexedDB database, behind a provider-independent reader.

This is a genuine new architectural authority — a third data class alongside
AD-014's Class A and Class B, a second database, and a new module boundary that
later phases will read through. AD-014 is unaffected: backtest *results* remain
Class B in their existing LocalStorage key, and nothing was reclassified.

Exactly one Architecture Decision was recorded. Continuous-contract strategy,
cloud synchronization, and a shared market-data service are explicitly not
decided here.

## Migration Impact

None. No journal IndexedDB version or object-store change, no LocalStorage key
migration, no trade or account migration, no backup-format change, no sync
change, and no Supabase schema change.

v1.6 introduces a **new** storage domain in its own database. That is not a
migration of existing storage.

Rollback is exact: revert the implementation and delete the market-data
database. Journal data is unaffected, and no journal backup is required to undo
this release.

## Known Limitations

Non-blocking. None of these is a release blocker.

P2:
- A failed import can leave a chunk for a UTC day that never entered a committed
  manifest. Such a chunk is not enumerable from the manifest and is therefore
  not removed by deleting that series. It is never reader-visible, cannot affect
  committed state, is reused by a retry of the same day, and is removed by
  clearing the cache or deleting the database. No staging store, orphan index,
  background collector, or chunk-store scan was added to eliminate residue that
  nothing can observe.
- Superseded chunk revisions are retained until the series is deleted or the
  cache cleared, deliberately, so that commit stays purely additive and a reader
  holding an older manifest can finish reading consistently.
- Ingestion has been exercised at three-day scale. Multi-year ingestion, and the
  record counts that come with it, have not been measured in a browser.
- Quota exhaustion is classified distinctly by the reused IndexedDB primitive but
  was not reached during acceptance.
- The database's blocked and version-change paths are wired through the reused
  primitive but cannot be exercised while only one schema version exists.

P3:
- The `mutation_lock_unavailable` path is unreachable on supported hosts, where
  the Web Locks API is available; it is proven by injection in unit tests rather
  than at runtime.
- Cross-tab evidence is one-directional: lock exclusion was proven with two real
  tabs, while the no-lost-update case was proven within one tab and in the Node
  harness.
- Absence counts for an export whose original window is not independently known
  cannot be derived from the file, and are therefore recorded as observations
  rather than stored as provenance.
