## Objective

Import real NinjaTrader futures activity as logical flat-to-flat journal
trades, preserving execution-leg detail so no source information is
irreversibly lost, while leaving manual entry, generic CSV/XLSX import,
Forex/CFD behaviour, analytics, and backup/restore unchanged. Two confirmed
v1.1 correctness defects adjacent to that path are repaired in the same
release.

---

## Delivered Scope

1. **NinjaTrader futures import (CSV only).** A source-specific adapter
   consumes a paired `Executions CSV` + `Trades CSV` export, reconstructs
   flat-to-flat position episodes, preserves execution legs, reconciles
   complete transaction costs, and emits the existing `RawTradeContent`
   contract. Supported broker-import roots are `NQ`, `ES`, `MNQ`, `MES`.

2. **Minimal additive leg foundation.** Imported trades may carry an optional
   `legs` array plus optional source-provenance fields. Historical and manual
   trades carry none of them and are completely unaffected. No migration.

3. **AM/PM import correctness.** `parseTime` previously discarded the meridiem,
   silently converting `1:05:00 PM` to `01:05` while passing validation. It now
   handles 12-hour input and fails closed on out-of-range values.

4. **Arabic CSV/Excel interoperability.** `buildExportCSV` now emits a UTF-8
   BOM so Arabic Notes render correctly when the export is opened normally in
   Microsoft Excel.

5. **Truthful import result counts.** A scoped P2 repair: the NinjaTrader
   success message reported episodes *discovered* as episodes *imported*, so a
   fully-skipped re-import wrongly claimed work had been done.

## Import Contract

- NinjaTrader import is **CSV only** in v1.2. NinjaTrader XLSX is deliberately
  deferred: the existing `raw:false` workbook path renders the source timestamp
  as a two-digit-year value with seconds dropped, while CSV preserves the exact
  source text.
- Generic CSV and XLS/XLSX journal import are untouched and remain the default
  import source.
- Both NinjaTrader files are required. Executions supplies episode structure
  and legs; Trades supplies the complete cost columns, which Executions does
  not expose.
- The adapter consumes CSV **text** and returns plain data; all browser file
  I/O stays in `ImportWizard`.
- Reconciliation is fail-closed and all-or-nothing. Nothing is persisted unless
  every check passes.

---

## Logical Trade Contract

One Journal Trade is one flat-to-flat position episode for the same source
account and source instrument: the position leaves zero, and the trade closes
when it returns to zero. Partial fills, intentional scale-ins, and partial
exits all belong to the same logical trade while the position remains non-zero.

Execution ID is provenance and ordering only. It is not logical-trade identity.

---

## Aggregate Contract

- `entryPrice` — quantity-weighted average of entry legs.
- `exitPrice` — quantity-weighted average of exit legs.
- `positionSize` — total entry-side quantity.
- `commission` — complete all-in episode cost.
- P/L, R, points, and outcome remain derived. NinjaTrader's `Profit` column is
  never read and never stored.

`positionSize` is total entry-side quantity, which is **not necessarily peak
simultaneous exposure** when an episode scales out and back in before going
flat. No existing consumer interprets it as peak exposure.

---

## Time Contract

NinjaTrader source timestamps carry no timezone marker and are treated as
already New York-local wall-clock time. No UTC conversion and no DST arithmetic
are performed or invented. The import UI states this assumption and requires
explicit acknowledgement before import is enabled.

Aggregate `entryTime`/`exitTime` are truncated to `HH:mm` to satisfy the
existing validation contract; legs retain full `HH:mm:ss`.

## Architecture Decision

**AD-021 — NinjaTrader Futures Import: Flat-to-Flat Journal Trade Identity and
Additive Leg Foundation** was recorded. Unlike v1.1, this release does create
durable architectural authority: it fixes what a Journal Trade *is* for
imported broker data, establishes a two-file fail-closed source contract, and
introduces the first additive optional fields on the trade shape.

## Known Limitations

- A weighted-average entry or exit price may be a long decimal, for example
  `29634.5833333333`. This is the true stored aggregate; the original fill
  prices remain in the legs.
- Internal floating-point representation can carry negligible numerical noise;
  user-facing money display is correctly rounded to two decimals.
- Dotted meridiem forms such as `P.M.` are outside the frozen AM/PM scope.
  NinjaTrader emits bare `AM`/`PM`, which is supported.
