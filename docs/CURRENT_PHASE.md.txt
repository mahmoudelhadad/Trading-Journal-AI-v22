## Phase

Phase 25 — Insights Evidence Transparency

Status:

COMPLETE

---

## Objective

Make the Insights page honest about the evidence behind each card,
without changing what any card says numerically or whether it appears.

Two defects, and only two. The empty state promised "at least 5 trades
with full data", a minimum nothing enforced — rules fire at n=1, and
the 5 existed nowhere as a constant, test, or architecture decision.
And the page header advertised "based on N trades" above cards resting
on much smaller populations: a setup/session/hour bucket gated at 2, a
plan-followed subset, a paired planned/actual-R subset, or two
different populations compared inside one sentence.

Everything else about the current rule behaviour is unqualified, not
incorrect. So this phase introduces no threshold, suppresses nothing,
and scores nothing.

---

## Scope (as delivered)

Nine string-literal replacements in pages/Insights.tsx — lines 213,
215, 217, 218, 224, 232, 243, 256, 271 — and nothing else.

1. R-01 header — "Automated analysis across ${n} visible trades ·
   individual insights may cover a smaller subset · Updated in real
   time". Deliberately hedged with "may", so it stays true for the
   cards genuinely backed by the whole population.
2. R-02 empty state — "Add more trades with relevant setup, session,
   plan, and R data to generate more insights". "Relevant", not
   "complete": different rules use different eligible populations, so
   a universal completeness claim would have recreated the removed
   falsehood in new words. No number replaces the 5.
3. R-03 Avoid Setup, R-04 Best Session, R-05 Best Entry Hour, R-06
   Risky Hour — each gained "across ${...n} trades" for its own
   bucket.
4. R-07 Plan Adherence — gained both subset sizes, planYes.length and
   planNo.length.
5. R-08 Execution Ratio — gained "across ${execPairs.length} trades
   with both a planned and an actual R".
6. R-09 Planned vs Real R — names BOTH populations: planned "across
   trades that have a planned R", actual "across all ${n} trades".

Every identifier interpolated was ALREADY in scope in the same useMemo
closure. No variable, expression, import, or type was added — which is
what made the change provably string-only.

Two cards were deliberately left untouched because they already
disclosed their population: Best Setup (line 212) and Overall Negative
P/L (line 247). The win-rate and avg-R cards were also left alone —
their population is the header's n, already named per AD-017 — as were
the streak cards, whose displayed number is the finding itself rather
than an estimate from a sample.

## Approved Decisions

None. No new architectural decision was made, so no ADR was written and
docs/ARCHITECTURE_DECISIONS.md.txt was not modified. This phase changes
presentation text only. Declining to add a component-test harness
inside a text-only phase is a scoping choice rather than an
architectural decision: adding jsdom + testing-library would have been
larger and riskier than the change it protected, and would have
introduced a new module class to a suite that is entirely pure-function
tests under calculations/. Playbook §9 requires an ADR for
architectural decisions and there is none here; Phase 24 set the
precedent of closing without one. AD-001 through AD-017 unchanged, not
reopened.

Note that AD-016 recorded small samples reaching fixed-threshold
analyses as "a known risk, not addressed". Phase 25 does not overturn
that acceptance — it makes the samples visible without gating them.

## Known Risks

Introduced by this phase:

- Low: R-02 and R-07 carry diff-verification only, not runtime
  observation. Their correctness rests on the V-trigger byte-identity
  proof plus typecheck. R-02's state is close to unreachable by
  construction — any population with at least one trade produces a
  win rate of 0% or 100% at n=1, which fires rule 1 — so it is
  unlikely ever to be observed without editing data.
- Low: disclosure does not soften imperative wording. "Consider
  removing it from your playbook" still reads as an instruction even
  when it now says "across 2 trades". This phase makes evidence
  visible; it does not adjudicate it.
- Low: the new header wording is itself a claim. It is deliberately
  hedged ("may cover a smaller subset") so that cards genuinely backed
  by the whole population do not make it false. Strengthening it to a
  universal promise would recreate the defect this phase removed.

Carried forward, unchanged:

- DEFERRED PRODUCT DECISION: minimum sample-size policy, and whether
  under-threshold rules should be suppressed or qualified. Phase 25
  deliberately does not settle this and must not be cited as having
  done so. Discovery established that a global gate over the visible
  trade count would be the wrong axis, since a large visible set can
  still contain a 2-trade bucket, a 1-vs-1 plan comparison, or a
  single execution pair.
- Low: rule 12's avgR / avgPlanned type selector misbehaves when
  avgPlanned is 0 or negative, while its body defensively prints 0%;
  and its avgR !== null guard is dead. R-09 discloses the mixed
  populations in words but corrects nothing.
- Low: Best Setup's inline "% win rate" uses an all-trades denominator
  without naming it — an AD-017 clause-1 gap at a site outside that
  AD's six-entry label map.
- Low: Best/Avoid Setup and Best/Risky Hour can name the same bucket
  when only one is eligible. Confirmed live twice: "Best Session: NY
  am" now reads "across 74 trades" unfiltered and "across 16 trades"
  filtered — in both cases the entire visible population, because only
  one session bucket clears n >= 2. Invisible before this phase,
  legible now; correcting the rule is out of scope.
- Low: bestDay / worstDay are computed and never consumed, producing
  two of the seven lint warnings.
- Low: the conditional hook call in Insights.tsx and its two eslint
  suppressions.
- Low: the same all-trades quantity renders as 22% on Insights
  (Math.round) and 21.6% in the Backtest table (fr.pct, toFixed(1)) —
  a display precision difference, not a formula or denominator
  difference.
- Low: getWinLossBreakdown's `closed` means DECISIVE, not closed;
  payoffRatio also returns null when avgLoserDollar is exactly 0;
  avgCommission's parseFloat tolerance; getWeekKey's timezone
  dependency at UTC offsets >= +12 or <= -12.
- Low: the FilterBar chip's "N of M" denominator is the total
  unfiltered count (Phase 22).
- Low: calculations/backtest.ts's stale composition header (Phase 24).
- Medium: onIndexedDbBlocked has no subscriber (G-3, Phase 6h).
  Unreachable at DATABASE_VERSION = 1, confirmed still 1.
- Low/Medium items from Phase 6g-2/6h.
- The 7 pre-existing lint warnings.
