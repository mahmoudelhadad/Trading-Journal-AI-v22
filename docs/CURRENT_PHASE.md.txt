## Objective

Deliver the first durable simulated-trading foundation for historical Replay:
owner-scoped resumable sessions, canonical manual Entry and full Exit, durable
progress and action history, deterministic concurrency and recovery, and strict
isolation from Journal, legacy Backtest and historical market-data storage.

## Delivered Scope

### Session and execution model

- Explicit owner-scoped schema-v1 session creation; ordinary Replay rendering
  never eagerly creates storage.
- UUID session, trade and action identity with immutable historical-series
  binding.
- One resumable active session model; explicitly completed Flat sessions are
  terminal immutable history.
- Manual Long and Short Entry, positive safe whole-contract quantity, one open
  position maximum and manual full Close Position.
- Optional immutable initial stop as a risk anchor only.
- ReplayRuntime-owned canonical execution from the latest fresh revealed
  1-minute close, with UTC decision, source-bar and fill identity.
- Rewind projection hides future history without deleting it, and mutations
  reject below the canonical action high-water mark.

### Persistence, concurrency and recovery

- Revisioned owner-scoped LocalStorage persistence serialized by Web Locks.
- Deterministic stale-revision conflicts, idempotent identical retries and
  same-ID/different-content collision protection.
- Outcome-unknown safety and explicit hydration recovery for committed and
  absent writes without automatic retry or fabricated actions.
- Pending and in-flight checkpoint ordering before Entry, Exit and Complete.
- Unresolved action/completion barriers block Replay movement, replacement,
  import and competing execution commands.
- Definite mutation and background-checkpoint failures preserve the last
  verified session, pause Replay and block unsafe progress.
- Previous-owner async results cannot publish after owner replacement.

### Isolation

- B2b sessions use authenticated owner-scoped physical storage.
- Journal and legacy Backtest raw storage remain unchanged by B2b operations.
- Historical market-data manifests and canonical bar chunks remain read-only.
- Existing B2a chart, reveal, import and browser-lifecycle contracts are
  preserved.

Final RA-27 used a real page-hidden browser transition while Replay was
genuinely playing. Replay settled when hidden, accumulated no hidden-time
catch-up, and resumed from the exact same canonical cursor after visibility
returned.

Final corrected RA-31 confirmed that ReplayRuntime remains authoritative.
`beginExecutionCommand` synchronously settles the monotonic replay clock and
captures execution context before checkpoint/persistence awaiting. Rendered DOM
clock text can lag that cursor between animation frames, particularly at 300×;
that rendering lag is not a delayed action-context capture defect.

RA-PERF ran in Chromium 151 on Windows with Web Locks using exactly 10 sessions
and 2,000 baseline canonical actions. The baseline envelope was 866,590 bytes.
The maximum verified mutation was 26.4 ms against a 100 ms threshold, with zero
threshold breaches, zero measured-operation long tasks and zero
measured-operation event-loop stalls. One 939 ms long task occurred outside the
measured mutation windows and was not a threshold breach.
